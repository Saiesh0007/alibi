Identity drift detection for AI agents

ALIBI

Before an AI agent acts, ALIBI asks why. Every action has to trace back to a job a human gave the agent. If it only traces back to a hidden instruction, it is stopped, even though the token is valid.

    The problem

    Companies give AI agents their own tokens and permissions. Security checks ask "is this token allowed to do this?" but not "is this agent still doing the job it was made for?" A hidden instruction in a document, a poisoned tool or a stolen token can change what an agent does while its token stays valid, so every permission check still passes.

    {{hidden}}

    How it works

    ALIBI sits between the agent and its tools as a proxy, so the agent's code does not change. It scores every tool call from 0 to 100 with three checks.

    01

    Role card

    A short YAML file per agent: its purpose, tools, data folders, destinations and limits. It is the baseline, so a brand-new agent is covered too.

    02

    Alibi trace

    Each key value in an action (path, URL, supplier, amount) is looked up in the human's task, the role card and what the agent read. A value found only in a hidden instruction has no alibi.

    03

    Baits

    Fake files and keys that no real job needs. Touching one quarantines the agent at once.

    0–39Allow
    40–69Hold, ask the owner
    70–100Block, remove misused scopes

    Slow drift

    A reporting agent is pushed a little further into finance files every day. Each single read is allowed, so only the trend can give it away. ALIBI compares each day's mix of actions with the agent's first two weeks (Jensen-Shannon distance plus a CUSUM alarm). That baseline only changes when the owner signs a new role card.
